# SALOON DREEM — نظام إدارة صالون الحلاقة

نظام عربي RTL لإدارة صالون الحلاقة من واجهة واحدة، مع تجربة عميل للحجز وبوابة إدارة للصالون، مبني على FastAPI وSQLite وTypeScript، ويعمل كتطبيق ويب قابل للتثبيت (PWA) مع تجهيزات تغليف Windows وAndroid.

**الإصدار الحالي: 1.2.0 — نسخة تشغيل أولية قابلة للاختبار وليست بعد خدمة إنتاجية مستضافة.**

## ما تم بناؤه

- إنشاء حساب المدير أول مرة، تسجيل الدخول والخروج، وتغيير كلمة المرور.
- تجربة العميل: استكشاف الخدمات، إرسال حجز حقيقي إلى قاعدة البيانات، الملف الشخصي المحفوظ محليًا، وسجل الحجوزات على الجهاز نفسه.
- إدارة الصالون: لوحة مؤشرات، المواعيد وحالاتها، العملاء، الحلاقون، الخدمات والأسعار، دفتر الدخل والمصروفات، إعدادات العمل والمظهر، وتصدير الحجوزات CSV.
- التحقق من ساعات العمل، منع تضارب الحجوزات للحلاق، ورفض الحجز في الماضي.
- تخزين كلمات المرور بتجزئة PBKDF2-HMAC-SHA256، ورموز دخول موقعة مع صلاحية زمنية وإبطال الجلسات عند تغيير كلمة المرور.
- الحد من محاولات تسجيل الدخول والحجز العام، والتحقق من التواريخ، ورؤوس أمان API.
- معالجة تصدير CSV لتجنب تفسير محتوى العميل على أنه صيغة تنفيذية داخل برامج الجداول.
- قاعدة SQLite محلية دائمة وإعدادات زمنية افتراضية لمنطقة `Asia/Gaza`.
- تصميم RTL متجاوب، دعم الوضع الداكن والفاتح، وملفات PWA الأساسية.
- اختبارات API للأمان الأساسي وتدفق الحجز والتعارض والتحصيل والمالية والإعدادات.
- ملفات GitHub Actions لاختبار المشروع وبناء Windows Portable EXE وAndroid Debug APK.

## تشغيل محلي على Windows

1. ثبّت Python 3.12 أو 3.13 وGit for Windows.
2. فك ضغط المشروع في مجلد تملكه، مثل `C:\Projects\SALOON-DREEM`.
3. انقر مرتين على `RUN-SALOON-DREEM.bat` أو افتح PowerShell داخل المجلد ونفّذ:

   ```powershell
   Set-ExecutionPolicy -Scope Process Bypass
   .\RUN-SALOON-DREEM.ps1
   ```

4. سيجهّز السكربت البيئة الافتراضية ويثبت الاعتماديات ويشغل الخادم ويفتح `http://127.0.0.1:8000`.
5. بعد نجاح التشغيل، شغّل `scripts\Create-Desktop-Shortcut.ps1` لإنشاء اختصار على سطح المكتب.
6. في أول تشغيل أنشئ اسم مستخدم وكلمة مرور مدير قوية؛ لا توجد كلمة مرور افتراضية. بعد تغيير كلمة المرور تُلغى الجلسات السابقة ويجب تسجيل الدخول مجددًا.
7. من فريق الحلاقين أضف حلاقًا نشطًا، وراجع الخدمات وساعات العمل. بعد ذلك يمكن للعميل إرسال الحجز.

البيانات الافتراضية موجودة في `data/saloon_dreem.db`، ومفتاح الرموز في `data/.token-secret`. لا ترفع أيًا منهما إلى GitHub. لا يحذف سكربت التشغيل قاعدة البيانات.

## تشغيل التطوير والاختبارات

```bash
python -m venv .venv
# Windows PowerShell: .\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m pytest -q
npm install
npm run check:types
npm run build:web
npm run check:js
```

واجهة API التوثيقية متاحة محليًا على `/api/docs`. يبدأ التطبيق تلقائيًا بقاعدة بيانات وإعدادات أولية لخدمات افتراضية؛ أضف فريق الصالون الحقيقي من داخل لوحة الإدارة.

## تطبيق Windows المحمول (Portable EXE)

ملف `.exe` لا يحتاج تثبيتًا يُبنى تلقائيًا من GitHub Actions على Windows. يغلف Electron الواجهة ويشغل خادم FastAPI محليًا. قاعدة بيانات نسخة Windows توضع في مجلد بيانات المستخدم الخاص بالتطبيق وليس داخل مجلد التثبيت. إذا أُغلِق التطبيق، يتوقف الخادم المحلي معه.

لا تتضمن النسخة شهادة توقيع كود من ناشر تجاري؛ لذلك قد يعرض Windows SmartScreen تنبيهًا عند أول تشغيل.

## تطبيق Android APK

يبني GitHub Actions ملف `app-debug.apk` عبر Capacitor. هذه نسخة Debug قابلة للتثبيت والاختبار الجانبي، وليست حزمة متجر موقعة بمفتاح نشر خاص.

لربط APK بالخادم المنشور:

1. انشر backend والواجهة على استضافة تدعم HTTPS وقاعدة بيانات دائمة.
2. افتح إعدادات المستودع على GitHub ثم **Settings → Secrets and variables → Actions → Variables**.
3. أضف متغيرًا باسم `MOBILE_API_BASE_URL` وقيمته عنوان HTTPS الأساسي، مثال: `https://saloon.example.com`.
4. شغّل سير عمل **Build SALOON DREEM** من **Actions → Run workflow** ثم نزّل artifact باسم `SALOON-DREEM-Android-APK`.

إذا لم يتم ضبط المتغير، يبني سير العمل APK لكن ستحتاج لإدخال عنوان الخادم من إعداد الاتصال في شاشة الدخول. لا توجد استضافة API عامة مرفقة بهذا المصدر، ولا يمكن للتطبيق على الهاتف مشاركة قاعدة بيانات جهاز الكمبيوتر عبر الإنترنت تلقائيًا دون نشر الخادم.

### نشر خادم تجريبي عبر Docker

يوجد `Dockerfile` و`docker-compose.yml`. للتشغيل المحلي:

```bash
docker compose up --build
```

سيستمع الخادم على المنفذ 8000 ويحفظ بياناته في مجلد Docker volume دائم. عند النشر الفعلي، استخدم HTTPS، وأمّن الخادم بكلمة مرور قوية، واحرص على وجود volume دائم ونسخ احتياطية. لا تعرض المنفذ مباشرة على الإنترنت دون طبقة HTTPS واستضافة مناسبة.

## رفع المصدر إلى مستودع GitHub الخاص بك

مستودع المشروع المستهدف:

`https://github.com/ibrahimrsaleem-wq/SALOON-DREEM`

بعد فك ضغط المشروع، افتح PowerShell داخل مجلد المشروع ونفّذ:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\Publish-To-GitHub.ps1
```

السكربت يهيئ Git عند الحاجة، ويتأكد أن المستودع البعيد ما زال فارغًا، ويتجنب الملفات السرية وقاعدة البيانات، ثم يحاول الرفع إلى `main`. لن يستخدم `force push`. يجب أن يكون Git مثبتًا، وأن يكون حسابك المسجل على جهاز Windows مخولًا بالكتابة إلى المستودع. إذا لم تكن صلاحية الكتابة متاحة، افتح GitHub وسجّل الدخول بالحساب الصحيح أو امنح ذلك الحساب صلاحية Write.

## حدود النسخة الحالية — بصراحة

- ملف APK وملف Windows EXE ليسا مرفقين جاهزين من هذا التشغيل؛ ملفات GitHub Actions هي التي تبنيهما بعد رفع المصدر وتشغيل CI.
- سجل «مواعيدي» والملف الشخصي والولاء الحالي في واجهة العميل يعتمد على التخزين المحلي في المتصفح/الجهاز. الحجوزات نفسها محفوظة في قاعدة بيانات الصالون، لكن عرض سجل عميل مشترك بين الأجهزة يحتاج هوية عميل آمنة، ويفضل OTP برسالة SMS أو قناة تحقق موثوقة.
- لا توجد بوابة دفع إلكتروني متصلة بمزود دفع، ولا تكامل SMS/WhatsApp/Google Calendar، ولا مفاتيح نشر Android أو شهادة توقيع Windows. التحصيل الحالي هو تسجيل محاسبي داخلي فقط.
- SQLite مناسب لنسخة محلية أو صالون صغير. للتوسع متعدد الفروع/الموظفين والاستضافة المتزامنة، خطط لترحيل قاعدة البيانات إلى PostgreSQL وإضافة صلاحيات مستخدمين وتدقيق عمليات ونسخ احتياطي ومراقبة. حدّ المحاولات الحالي داخل الذاكرة طبقة حماية أولية لعملية واحدة؛ النشر العام متعدد العمال يحتاج أيضًا إلى حد مركزي على مستوى بوابة API أو reverse proxy.
- أجرِ مراجعة أمنية واختبار قبول عملي قبل التعامل مع بيانات عملاء حقيقية أو فتح الخدمة للإنترنت.

راجع أيضًا [`BUILD-STATUS.md`](BUILD-STATUS.md) لمعرفة ما تم اختباره فعليًا وما يزال بانتظار البناء/النشر.

## الخصوصية والأمان

لا تضع `.env` أو قواعد البيانات أو الرموز السرية في GitHub. استخدم HTTPS وأسرار الاستضافة، وفعّل نسخًا احتياطية مختبرة، وقلّل الوصول إلى بيانات العملاء. اقرأ `docs/ARCHITECTURE.md` و`docs/DEPLOYMENT.md` قبل النشر.
